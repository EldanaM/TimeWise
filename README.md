#  TimeWise - Умный тайм-менеджер

##  Описание проекта

TimeWise помогает планировать задачи и анализировать продуктивность. Приложение собирает статистику о реальном времени выполнения и предупреждает, если оценка слишком оптимистична.

**Что умеет:**
- Создавать задачи и категории
- Отслеживать фактическое время выполнения
- Анализировать точность планирования
- Присылать уведомления о нереалистичных оценках
- Показывать статистику и достижения

---

##  Стек технологий

**Backend:** Python, Django, Django REST Framework, SQLite  
**Frontend:** React, CSS  
**Инструменты:** Git

---

1.  **Какие основные функции реализованы в приложении?**
    Управление задачами (создание, удаление, отметка о выполнении), категории задач, учет времени выполнения, уведомления о расхождениях с планом, статистика и дашборд.

2.  **Как пользователь взаимодействует с системой?**
    Через веб-интерфейс (React) или API-запросы. Через веб-интерфейс пользователь создает задачи, указывает время, отмечает выполнение, получает уведомления на сайте.

3.  **Какие данные хранит система и для чего они используются?**
    Пользователи-для авторизации, категории-для группировки задач, задачи, временные метки-для анализа времени, уведомления.Используются для статистики и сравнения плана с фактическим временем выполнения.

4.  **Как реализована логика работы с задачами или временем в приложении?**
    Задачи имеют оценку времени, при выполнении фиксируется фактическое время, система сравнивает плановое и фактическое, создает уведомления при расхождении.

5.  **Как организована структура проекта и зачем код разделён на разные файлы или модули?**
    Разделение на бэкенд (Django) и фронтенд (React). Такое разделение упрощает поддержку и масштабирование.

6.  **Какие основные компоненты или модули приложения можно выделить?**
    Модели (Category, Task, TimeLog, Notification), API ViewSet'ы (обработка запросов), сериализаторы, сервисы аналитики, сервис уведомлений, фронтенд компоненты React.

7.  **Как происходит взаимодействие между различными частями программы?**
    Фронтенд отправляет HTTP-запросы к API Django. ViewSet'ы вызывают сервисы для бизнес-логики. Сервисы работают с моделями и отправляют уведомления.

8.  **Как реализована работа с базой данных или хранением данных?**
    Данные хранятся в SQLite. Django сам создает таблицы на основе моделей и управляет данными через удобные команды.

9.  **Как приложение обрабатывает пользовательские действия или запросы?**
    Каждое действие (создание задачи, отметка о выполнении) вызывает соответствующий метод API, который обновляет БД и запускает проверки (уведомления).

10. **Какие механизмы используются для обработки ошибок или некорректных данных?**
    Базовая валидация в сериализаторах, проверка прав доступа в ViewSet'ах.

11. **Какие сильные стороны архитектуры этого проекта вы можете выделить?**
    Разделение на бэкенд и фронтенд, модульная структура, использование DRF для API.

12. **Какие проблемы или ограничения есть у текущей реализации?**
    Нет тестов, жестко заданные пороги для уведомлений, в части аналитики просто статистика без ML.

13. **Какие функции вы бы добавили в приложение и почему?**
    Фоновые задачи, более гибкие настройки уведомлений, интеграция с Google-календарем, уведомление в Telegram.

14. **Какие изменения в коде могли бы улучшить масштабируемость проекта?**
    Переход на PostgreSQL, оптимизация запросов, добавление пагинации для больших списков.
